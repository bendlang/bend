# Fixed private lists inside the complete scalar guard

The disposable guard-allocation variant passes its direct runtime, generated
program and independent reflection-order controls. Both confirmations are
positive but below the prospectively frozen benefit thresholds, so the change
is deferred. No compiler/runtime source changed for this experiment.

The prospective [design](../../design/phase30/scalar-guard-fixed-lists.md)
separates this experiment from the earlier guard-bypass/outlined-fallback
diagnostic. It hoists only private fixed prototype/key lists and replaces the
four-element descriptor array/every callback with ordered explicit own-data
checks. All four metadata reads still occur before those checks. Scalar capture,
snapshot timing, public code, exact-entry permission and every acceptance
predicate remain unchanged; no result cache or invalidation scheme is added.

The standard-intrinsic scope is unchanged. Patched Array iterators/every and
reflection methods are not a supported execution domain. The independent
reflection instrumentation is diagnostic evidence of retained operation order,
not an expansion of that production contract. Fixed lists remain inaccessible
to public callbacks and the original primitive-prototype list is never mutated.

`prototype-guard-lists-02/derive.json` binds checked actual14 helper/original
Mandelbrot emissions and the same frozen runtime core. Exact reconstruction
shows that each module changes only the guard body and private fixed constants.
The unchanged helper baseline is the checked14 module that already matches
checked12 bytes; its receipt retains its actual14 acquisition identity.

The first derivative failed before producing a candidate because its expression
parser masked preceding runtime line comments as expression text. Exact failed
source and traceback remain at `prototype-guard-lists-01/failed-derive.py` and
`prototype-guard-lists-derive-01-outer`. The corrected attempt parses the known
guard function locally; it does not alter the intended rewrite. Fresh02
derivation and every subsequent gate pass.

The independent reflection suite observes getOwnPropertyDescriptor,
getPrototypeOf and hasOwn sequencing, including metadata failures and early
returns. No installed metadata getter is invoked during validation. Direct
core and full emitted-program suites use separate immutable diagnostic outputs.

Frozen `guard-lists-plan-02` contains a paired helper/original screen,
`confirm-helper.json` using the maintained confirmation, and `long-whole.json`
using the unchanged 15-second-warmup runner. All source/receipt/design/control
identities are bound. Before the screen, the parent froze a minimum benefit:
at least 5% stable reduction in helper time or 3% in whole-program time, with no
confirmed regression above 3% on the other. Both source changes form one
temporary-allocation variant; no separate causal attribution is claimed.

## Retained timing windows

The exclusive CPU3 `guard-lists-screen-02` completes in 8.68 seconds with every
result passing. Helper medians are 0.007474 ms baseline versus 0.007287 ms
candidate, an apparent 2.50% saving; whole-program medians are 0.306016 versus
0.294722 ms, an apparent 3.69% saving. Helper measured halves improve roughly
9–12%, and whole-program halves improve 21–24%, so both are screening evidence.
The unchanged frozen confirmation protocols were selected before judging the
decision threshold.

`guard-lists-helper-confirm-02` completes in 42.79 seconds:

| Helper output | Median ms | Sample range ms | Half-change range |
| --- | ---: | ---: | ---: |
| Actual14 baseline | 0.00696200 | 0.00689864–0.00699945 | +1.59% to +3.05% |
| Complete-guard allocation variant | 0.00666057 | 0.00661500–0.00673793 | +0.03% to +2.64% |

The ranges are disjoint and the measured reduction is **4.33%**, below the
frozen **5% helper threshold**.

The separate 15-second-warmup `guard-lists-whole-long-02` completes in 129.59
seconds, with every result passing:

| Original Mandelbrot output | Median ms | Sample range ms | Half-change range |
| --- | ---: | ---: | ---: |
| Actual14 baseline | 0.216142 | 0.214937–0.220476 | −0.45% to −0.18% |
| Complete-guard allocation variant | 0.212245 | 0.211743–0.213471 | −0.34% to +0.38% |

This gives a stable **1.80% reduction in time**, below the independently frozen
**3% whole-program threshold**. Both sample ranges are disjoint, so this is not
a claim of zero effect; the effect is too small for the precommitted promotion
criterion. Neither threshold is relaxed after measurement. Defer the runtime
change and preserve all outcomes. No extra variant, cache or broader ABI rule
is justified before final compiler release.
