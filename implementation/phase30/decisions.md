# Phase30 experiment decisions

This is a decision index, not a final performance matrix. **Production** below
means included in the maintained candidate through checked attempt17. The
complete attempt14 comparison exposed generic-workload regressions; independent
runtime attribution identified the selected-arm entry mechanism. Attempt15
restored generic delayed application, and attempt16 removed the obsolete arm
module and runtime bridge. The full16 timing matrix exposed a residual RLE
regression; P30-030 subsequently met its prospective criteria and its three
runtime edits are included in checked17. **Fresh17 affected gates and final
measurements remain separate from these historical decisions.** Each
number belongs to the named input, compiler images and measurement window in
its linked report. Historical incremental gains must not be multiplied.
“Correctness passes” always refers to the stated controls and admission scope,
not a proof of full backend conformance. Sample ranges and remaining warmup
drift stay in the canonical reports.

The main accepted progression is broader closed scalar work using the existing
KTerm and JS machinery, followed by small emitted-code changes. It is not an
argument to drop runtime guards globally or introduce an additional compiler IR;
the [native IR reuse audit](native-ir-reuse-audit.md) records why the existing JS
representation was the smaller integration path. [Selected integration](final-integration.md)
and [checked-source controls](source-scalar-tree-controls.md) identify which
compiler images were actually validated. The final same-window original-program
and compiler-throughput results must be reported independently of this history.
