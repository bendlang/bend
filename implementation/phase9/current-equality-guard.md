# Current-emitter equality guard

The current upstream helper can compare **all primitive JavaScript strings with
`===`**, including malformed UTF-16. The version-3 derivative removes the two
`isWellFormed` calls from the current fast path. Legacy version 1 retains its
original guard; current version 2 remains exactly replayable. Root independently
reviewed the isolated patch and authorized applying it after the scoped controls
and operation screen passed. Integrated compiler timing remains a separate gate.

The [P9-006 plan](../../experiments/phase9/P9-006-current-equality-guard.md) was
written and preserved before the isolated candidate. No upstream compiler source
or generated user-program semantics was changed by this experiment.

## Why the current helper permits this

The exact checked integrated-02 artifact, generated by b2111cf, decomposes a
nonempty string using `codePointAt(0)` and a one- or two-code-unit slice. A valid
surrogate pair becomes a value above 65535; every other code unit, including an
unpaired surrogate, keeps its value at or below 65535. This decomposition is
injective: each value above 65535 reconstructs one unique surrogate pair, and
each remaining value reconstructs one code unit. Concatenating the reconstructed
tokens recovers the original UTF-16 string.

`Char.cmp` compares these numeric values through `cmp_new`; `String.cmp` returns
EQ exactly when both strings end together and every token compares equal.
`String.eq.fin` discards reconstructed strings and tests that EQ result. Therefore
it returns true exactly when the original UTF-16 code-unit sequences are equal,
which is the primitive-string `===` condition. This reasoning includes empty
strings, mixed paired/unpaired boundaries and lone surrogates. The current path
does not call `char_new`; that validation remains significant in the legacy
emitter, where equal malformed strings can throw.

The inspection covers the exact seven protected equality/comparison bodies and
four protected runtime helpers: `String.eq`, `String.eq.fin`, `Cmp.is_eq`,
`String.cmp`, `Char.cmp`, `String.cmp.fin`, `String.cmp.rec`, `run_loop`, `run_lib`,
`char_new` and `cmp_new`. Their complete inspected slice is preserved as
`attempt-01/reviewed-dependencies.js`. Existing exact body hashes and the full
generated-runtime prefix hash remain required; this is not a heuristic rewrite
of arbitrary JavaScript.

Both primitive type checks remain. Every non-string input executes the original
helper body, retaining object access and error order. The claim retains the prior
assumptions of standard unmodified JavaScript built-ins and excludes resource
exhaustion, reflection and monkeypatched-host equivalence. Removing calls to a
monkeypatched `String.prototype.isWellFormed` would be observable outside that
domain.

## Versioning and evidence

The isolated patch adds a current version-3 profile and an optional numeric
`transformEquality(source, version)` argument. Fresh current derivations select
version 3; verification explicitly replays the recorded transform version.
Versions 1 and 2 preserve their bytes and statistics. Unknown versions and
cross-emitter selections are refused, while runtime/body/export grammar,
bootstrap/source/Base/recipe identity and revision cross-binding remain guarded.

Before production application, the existing boundary suite passed 12 current
groups and 11 applicable legacy groups (plus one explicitly inapplicable legacy
registration). The bounded differential screen then completed in **6.15 seconds**:

- 262,144 comparisons covering every single UTF-16 code unit against itself,
  a different code unit and the empty string in both directions.
- 2,097,152 comparisons covering all 1,048,576 valid surrogate pairs, both equal
  and unequal cases.
- 12,321 representative short-string pairs, 10,000 deterministic arbitrary-UTF-16
  fuzz pairs and 72 common-prefix/boundary pairs.
- 27 non-string and observable fallback-object cases, preserving exact access
  logs and outcomes across genuine, version-2 and version-3 helpers.
- Exact version-1/version-2 transform replay, recorded version-2 lineage replay,
  and genuine version-3 derivation/replay.

All **2,381,689 primitive pairs** agree across the genuine helper and both
derivatives. The actual generated public API behavior remains covered by the
boundary suite, including zero arity, currying, extra arguments and input
immutability. The differential screen used Node 24.18.0, CPU2 and the compiler's
4096-KiB stack setting; its 20-second deadline was not reached.

The same process ran four ABBA blocks, eight samples per variant per workload,
with 100,000 comparisons per sample and explicit result checks:

| Operation workload | Version 2 median | Version 3 median | Ratio |
| --- | ---: | ---: | ---: |
| Compiler tags | 4.84 ms | 1.24 ms | 3.91× |
| Identifiers | 5.49 ms | 1.86 ms | 2.96× |
| Unicode identifiers | 10.68 ms | 1.97 ms | 5.41× |
| Long prefixes | 8.38 ms | 4.88 ms | 1.72× |
| Malformed UTF-16 | 172.56 ms | 1.65 ms | 104.72× |

This is a **same-process operation screen concurrent with other development**,
with warmup, short samples and no whole-compiler speed claim. Malformed strings
benefit especially because version 2 deliberately fell back to recursive
comparison; that workload is not evidence of ordinary compiler frequency.

The helper was applied only after an exact live/preimage byte check. Its SHA-256
changed from `d32bbc13ef296b665e07c374a8817a01f659343d05f933e60011b51066003130`
to `f4b438ae57744e1c15dd5303fdc8a7d4317a5e37ee064f466a311834bb1565f8`.
The maintained suite adds an explicit version-replay/refusal group.

## Retained resource-boundary observation

The first final-suite rerun with Node's default stack completed 12/13 groups.
The original recursive helper overflowed on the 4096-character control while
the derivative returned true. The new version-replay group passed. This is an
observable resource-exhaustion difference, explicitly excluded by the existing
derivative contract; it is preserved in `final-groups-01`, not silently discarded
or converted into a semantic pass. The separately retained `final-groups-02`
rerun uses the compiler's 4096-KiB stack and passes **13/13 current groups** and
**12 applicable legacy groups**, with the thirteenth legacy registration
explicitly inapplicable. The new version-replay/refusal group passes on both
emitters. No other compiler job was launched for this experiment.
