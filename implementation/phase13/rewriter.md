# Phase13 structured branch workers

The [prospective experiment](../../experiments/phase13/P13-002-structured-branches.md)
has reproduced all five authentic derivation versions exactly and produced an
isolated normalizer branch-worker pilot. **Plain worker lifting is rejected:
same-source checking is 1.01% slower.** Production source, maintained helper,
runtime and release remain unchanged. Correctness, performance and promotion
decisions below have separate scopes.

## Exact compatibility and shared representation

`selfhost/build/phase13/rewriter-stage1-01/report.json` records passing authentic
versions 1–5: generated bytes and the exact serialized statistics match both their
historical artifacts and the maintained implementation. Version 5 reproduces API
`0975a4a805409cfd6a721f72cd4ffac6b207045cdecb8aa5ef04955297fcd697`
from the verified Phase12 checked parent
`a8453133f37a0965b7291795af2e06c7c65e3ee7c97a8ff4b14b98cfba2e5568`.

[rewriter-structure.mjs](../../selfhost/tools/performance/phase13/rewriter-structure.mjs)
shares token ranges, module/function views, call/arrow recognition, branch ranges,
binding guards and source-preserving rendering.
[rewriter-v5.mjs](../../selfhost/tools/performance/phase13/rewriter-v5.mjs)
uses that view for the existing choice and leaf passes. Earlier scalar passes
still come from the complete frozen Phase12 helper. This proves compatibility,
not a maintained line-count reduction: the experimental shared layer has 172
physical lines / 7,947 bytes and its version adapter 66 lines / 4,494 bytes, in addition
to the frozen helper dependency. A maintained replacement would have to retire
the duplicate implementation and retain authentic history explicitly.

## First worker pilot and operation tradeoff

The profile-selected `$norm_eval_node$` family has seven remaining choices.
`selfhost/build/phase13/rewriter-norm-eval-01/manifest.json` binds the isolated
API `d74ecdbd243bb1bafe4ed726b1b697ccb3b942ca39a0b7a8dfe27e5ff5581554`,
its parent, Base/runtime, helper dependencies and exact replay report. It creates
14 named workers with 63 static capture parameters. Each selected message carries
Unit plus 2–5 identifiers; the previous message carried only Unit. Branch bodies
remain in separate workers, retaining original non-tail calls and nested work.
The initial domain permits immutable parameters and parenthesized one-parameter
block arrows; it rejects declarations rather than attempting general TDZ analysis.

[rewriter-counts.mjs](../../selfhost/tools/performance/phase13/rewriter-counts.mjs)
counts operations on instrumented copies of the actual baseline and candidate.
`selfhost/build/phase13/rewriter-counts-01/report.json` preserves inputs, both
instrumented images and exact loaded books/check results. All three valid module
graphs match; their load phase never enters this family. Checking gives:

| Definitions per module | Selected closures replaced | Dispatches, unchanged | Extra capture-array slots | Total slots, baseline → workers |
| --- | ---: | ---: | ---: | ---: |
| 4 | 294 | 1,652 | 1,470 | 1,815 → 3,285 |
| 16 | 1,086 | 8,366 | 5,430 | 9,333 → 14,763 |
| 64 | 4,254 | 60,344 | 21,270 | 70,287 → 91,557 |

The pilot replaces each selected closure with one worker invocation. It does not
reduce trampoline dispatches. Fewer calls to `run_tail` merely reflect direct
construction of the same number of messages; counting those calls alone would
give a false allocation claim. The weighted capture-slot increase is five per
selected branch on these inputs. These are operation counts, not elapsed-time or
heap-allocation measurements; V8 may optimize the two representations differently.

Independent resource screening in
`selfhost/build/phase13/measure-norm-eval-history-01/report.json` passes fresh
long-string checks and paired exact 53/60-request histories (226 observations),
with unchanged 4 MiB stack / 4 GiB heap. Helpers, complete transform reports and output
bytes replay before and after the gate. This establishes these resource controls
for the exact known family, not general stack equivalence or promotion readiness.

## Preserved guard failures and correction

The independent actual-transform controls in
`selfhost/build/phase13/control-lift-01/report.json` found four semantic failures
in the first lifter: a parameter named `undefined` was mistaken for the global,
and captured `<<=`, `>>=` and `>>>=` assignments escaped the write guard, breaking
binding sharing with a saved closure. An unparenthesized arrow was also accepted
outside the stated grammar, although that witness retained its value. Original
tools, candidate and consumed controls remain unchanged. The known normalizer
family contains none of these constructs; its resource/count evidence does not
excuse the generic guard failures.

The separate
[rewriter-lift-v2.mjs](../../selfhost/tools/performance/phase13/rewriter-lift-v2.mjs)
resolves lexical bindings before allowed global spellings, distinguishes shift
assignment from comparison and requires every arrow to match the admitted binding
grammar. It is 120 physical lines / 7,712 bytes, before counting the shared view,
adapter, frozen historical helper and tests. Independent correction controls and
a newly identified candidate are separate from the first attempt. The corrected
candidate in `selfhost/build/phase13/rewriter-norm-eval-02/manifest.json` replays
to the same `d74ecdbd…` API bytes, with its own helper and report identities.
`selfhost/build/phase13/control-lift-02/report.json` passes all 17 actual-transform
controls: the four semantic counterexamples now capture correctly or refuse,
unsupported arrows refuse, member/property-key/tag-key cases retain their values,
and protected runtime/generated parameter shadows refuse through the existing
version 5 prerequisite. This closes the identified guard errors; it does not
reverse the failed performance hypothesis or authorize production promotion.

## Controlled screening rejects plain lifting

Root's serial CPU0 ABBA in
`selfhost/build/phase13/measure-norm-eval-pilot-01/report.json` passes all four
exact complete same-source results. Fresh Node 24.18.0 processes use unchanged
4 MiB stack / 4 GiB heap, host, source and runtime, separately validated API-specific
Base caches, and no intentional concurrent compiler/archive jobs. Cache preparation
and transformation are outside measurement; OS caches are not flushed. Process
time includes startup, verification and capture; request time wraps the unchanged
adapter probe, including lazy API loading.

| Mean of two samples | Released Phase12 | Plain worker pilot |
| --- | ---: | ---: |
| Process wall | 27.454s | 27.732s |
| Request | 26.307s | 26.584s |
| Maximum observed RSS | 1,339,616KiB | 1,331,100KiB |

The candidate is 1.01% slower by process time, with no evidence of a useful gain;
the small RSS difference is insufficient to justify the new implementation.
This refutes the selected family's performance hypothesis under the recorded
workload. It does not establish that every form of closure conversion is slower.
No extra families or broad compiler suite are warranted for this rejected pilot.

The independent complexity audit at
`selfhost/build/phase13/measure-preparation-01/complexity-pilot-report.json`
counts 858 physical lines including 355 new pilot lines, 296 retained helper lines and
207 retained test lines, versus 503 for the current helper and tests. Version 2 adds
three more lines. These totals exclude additional experiment harness/control code;
there is no complexity reduction to offset the absent speed improvement.

Phase12's broad-inlining and normalizer-seed counterexamples remain hard stop
conditions. Root owns any subsequent controlled timing and the separately planned
selector-fusion alternative, which targets intermediate messages while keeping
selected bodies in their original arrow frames. The worker pilot remains research
evidence only, with its failures and consumed tools preserved.

enters this family. These counters establish removed work, not a speed estimate;
root's separate semantic, resource and timing gates decide the candidate.
