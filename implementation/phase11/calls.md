# Phase11: guarded literal-choice lowering

The checked B1 compiler creates two wrapper closures at each literal `kc` or
`f_choose` branch, although it uses only one branch. A guarded derivation removes
those wrappers at 1,188 compiler call sites while preserving the runtime's tail
message. On the small valid loading/checking graphs, measured wrapper calls fell
to zero and tail-message counts stayed identical. The maintained version4
derivation passed its checked workflow and correctness gates. The root's final
controlled comparison determines the performance gain; this investigation makes
no whole-compiler speed claim.

Prospective experiment: [P11-004](../../experiments/phase11/P11-004-calls.md).
All paths below starting `build/` are relative to `selfhost/` and are retained by
the Phase11 evidence publication. Production integration and release acceptance
belong to the root report.

## Why this opportunity exists

The pinned TypeScript emitter already emits saturated ordinary calls directly.
Repeating ordinary uncurrying would not address the present cost. Prior Phase4/5
ordinary-call experiments found weak or absent opportunities; the Phase6 worker
variants carried a separate unresolved malformed-input boundary. Those earlier
timings are not evidence for this candidate.

The Bend JavaScript emitter already recognizes choice combinators, but B1 is
generated by the pinned upstream emitter. Its checked output contains calls of
this form:

```js
$kc$(condition, run_clo(yesArrow), run_clo(noArrow))
```

The verified runtime's `run_clo` allocates a callable wrapper, attaches its
underlying arrow, and installs a reverse pointer. The verified choice body calls
`run_tail` on the selected wrapper with a Unit value. `run_tail` unwraps that
fresh wrapper before constructing a tail message. The derivation instead emits:

```js
run_tail((condition) ? (yesArrow) : (noArrow), {$:"Unit"})
```

Both wrappers, their pointer writes, and the unchosen arrow allocation disappear.
The chosen arrow and tail message remain. A direct ternary IIFE would lose the
tail boundary and can overflow the JavaScript stack; this implementation does
not use that formulation.

The fresh profile separately found substantial `run_loop`, `run_tail`, and GC
sample shares. Those observations motivated investigation but do not attribute
all dispatch or GC cost to choices. The operation counts below supply narrower
causal evidence.

## Accepted domain and correctness boundaries

This is a derivation of a genuine checked B1 image for the reviewed upstream pin,
not a new bootstrap, fixed point, upstream emitter change, or change to emitted
user programs. Bend compiler source remains unchanged by this candidate. The
existing equality derivation's strict tokenizer is reused; no additional
production tokenizer or dependency is introduced.

The transform verifies the runtime prefix and exact protected `kc`/`f_choose`
bodies, requires a saturated call with two literal `run_clo` arrow arguments,
and preserves the existing runtime and export marshalling. It rejects protected
name shadowing, rebinding, destructuring, nested or duplicate declarations,
property/member callees, and unsupported protected references. Nonliteral thunk
arguments are left unchanged. Recognition is not based on a callee name alone.

The condition executes once, with the original JavaScript truthiness. Branch
captures, selected-only effects, Unit argument, returned functions, raw tail
messages, error order, public currying, and extra arguments are covered by
controls. A 100,000-iteration tail case stays stack safe. Malformed raw values
are distinct from the ordinary typed public graph tests. Error comparisons cover
name, message, and demand order; reflective stack strings are not an invariant.
The standard unmodified runtime/builtins assumption excludes arbitrary prototype
mutation, proxies, accessor injection, and reflective function identity tests.

Version4 is the default only for the current reviewed pin. Explicit versions1,
2, and3 retain their original transformation bytes and statistics. The old pin
still defaults to its previous profile. Existing `verifyAttempt`, derivation
replay, release installation, and release verification consume the maintained
metadata without an ad hoc installed API.

## Counts and excluded timing screen

The disposable counter images count actual `run_clo` and `run_tail` calls during
successful public graph loading followed by checking. They are separate from
the timing images. Counts in `call-micro-01/report.json` were produced directly
in the owning process before any child launch.

| Definitions | Baseline wrapper calls | Candidate wrapper calls | Tail calls, both |
| ---: | ---: | ---: | ---: |
| 16 | 24,248 | 0 | 12,124 |
| 64 | 122,968 | 0 | 61,484 |
| 256 | 902,552 | 0 | 451,276 |

This is elimination of wrapper operations on these workloads, not elimination
of all allocation or dispatch. The actual compiler contains1,188 accepted sites
and no skipped choice call in this image.

The small ABBA screen retained four worker outputs and six operation rows,
including a slower candidate result for checking256 definitions. During report
audit, every worker launcher was found to contain `spawnSync taskset EPERM`
despite status0. The launcher had checked status alone. **All timing ratios from
this screen are excluded from performance acceptance**, even though completed
worker files exist. Root's controlled final comparison supersedes this screen;
it was not repeated. The corrected launcher rejects an error or signal and
requires a completed worker output. Original tool, reports, samples, and negative
result remain intact, with the audit in
`call-maintained-02/launcher-audit.json`.

## Preserved failures and conclusion

`call-selected-01` failed before observations because the isolated host lacked
`src/compiler.json`; the corrected fresh attempt02 copied the needed source.
`call-maintained-01` completed bootstrap but failed helper import because a
JavaScript string replacement interpreted the literal `$'` sequence and corrupted
the inserted text. The corrected preparer uses replacement callbacks; attempt02
passed syntax checks before its real workflow. Both failed projects and consumed
tool versions remain available.

`call-maintained-02/release-controls-01` also had the status-only launcher defect:
its four CLI records carried EPERM. Its original pass field does not establish a
valid CLI gate. That report is retained and explicitly superseded by the fresh
permitted `release-controls-02`, whose four child launches had no error or signal
and the expected version/check output. Integrity checks alone were never treated
as proof of CLI execution after this audit.

The candidate removes demonstrably redundant allocation through a small guarded
extension to the existing derivation path. It preserves a real tail boundary and
historical artifact replay. Its correctness and operation evidence justify root
integration; the root's final comparison decides its end-to-end benefit. No
additional compiler jobs or standalone whole-source timing are needed here.
