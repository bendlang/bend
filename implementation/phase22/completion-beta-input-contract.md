# Direct-control input contract review

The frozen 17-row completion suite tests a materialization helper on trusted, already-scoped IR. It does not exercise a public loader ABI accepting arbitrary external trees. Thirteen inputs are ordinary finite graphs built from Ref, Var, Lam, App, All, Ctr and Let; four additionally contain an intentionally incomplete object with a throwing tag getter. Those four poison objects are demand witnesses, not legal Bend values. Their results cannot alone establish source-language acceptance or error-order regressions.

Binder IDs are distinct lexical IDs, including same-spelling inner shadowing. The suite does not authorize `f_sub` to ignore binders in arbitrary graphs that reuse a binder ID. Generated high-bit pattern IDs, arbitrary free positive IDs, malformed quantities/ranges and unknown term tags are outside this suite. Constructor names require no book lookup in the tested pinned higher/lower operation; this does not assert that the containing program type-checks.

The negative control is `FUnboundVar(name=g,id=0,quant=1,origin=0/0)`, projected to pinned `Var(g,-1)`. Its quantity field is not interpreted in this representation. Actual contextual marked-name syntax has a max-U32 Var inside an FName and an `FUnboundVar` value fallback (quantity 0); the latter is the semantic negative sentinel after materialization. A generic max-U32 Var should not be silently treated as negative without a separate representation contract.

Success comparison alpha-renames only bound IDs and leaves free IDs fixed. It preserves term tags/names, lambda quantity presence/value, All/Let quantities and real term ranges. Let's per-binder bookkeeping nodes do not exist in the pinned Let representation, so their private ranges are not an equality claim. Complete candidate graphs remain available. Error comparison retains exact message, note and selected span. No candidate term is passed through TypeScript evaluation during comparison.

The confirmed absent-origin beta result is a valid helper-level discrepancy: pinned substitution adopts the occurrence span only when the replacement has no span and is not a negative variable. Located replacements and the sentinel behave correctly. Public parsed-source reachability of that unlocated argument still requires an independent source witness. The failed poison reads arise from `f_context_material_next` testing the tag of a higher-stage deferred child; natural operator errors inside a discarded lambda already remain unforced correctly.

The suite does not cover explicit Sub nodes, annotation stripping, term cells/HOAS functions supplied externally, or arbitrary raw trees from historical f_parse. ABI2 retirement should define supported completed-source inputs rather than preserve those artificial external contracts. This is a scope review, not a new test run or waiver of either retained failure.
