## Finding

The uncommitted JReadCall implementation is consistent with its proposed typed
producer/consumer proof. I found no semantic blocker in the reviewed bytes.
This is static approval for a checked build and focused correctness acquisition,
not a release approval or a claim of measured benefit.

j_region_args first validates and transforms every producer argument. Native
Array.get recognition checks provenance, arity, erased U32 and native telescope.
j_region_read_call then requires that transformed native node as the final
argument. j_region_read_consumer examines the already completed private helper;
it requires JUnpack at its last input slot, exactly two fields and the canonical
array/value Sigma. j_region_unpack stored a weak-head-normalized input type, so
the pair predicate does not accidentally treat an unreduced alias as a tuple.

The bridge invocation uses j_region_read_args to retain ordinary prefix arguments
and then the original erased-slot/array/index argument list. JavaScript evaluates
those left to right before bridge entry. The bridge then evaluates arraydata and
Number(index) modulo data.length and reads the backing scalar before the consumer
arm. This matches arrayget's existing read point and preserves unused reads. It
does not turn the scalar into a delayed lookup, nor store it back into the array.

The field slots are arity and arity plus one, following the removed final tuple
parameter at arity minus one. Existing source binders use a different emitted
namespace. The $get suffix cannot collide with the delimiter-separated decimal
code-point helper name. Nested field bindings have their own scopes and retain
the prior simultaneous-let rules. Initial-zero rebinding remains unchanged.

The native dependency is retained in the region guard set. Original public
helpers, generic fallback, argument mutation, raw descriptor calls and nonmatching
private call sites keep their old implementation. No new runtime ABI is added.

## Limits and required observations

The production bridge combines read and consumer in one function, while the
saved-output experiment used a separate bridge and clone. Therefore the earlier
order witnesses are supporting evidence, not an execution test of these bytes.
The next acquisition must observe the actual replacement read and compare native
events, including earlier argument writes, consumer writes, unused reads and
wrapping indices. It must retain the existing full-pair and independent-fold
oracles and public-boundary controls.

Eligible consumers get a duplicate bridge body even if no fused producer uses it.
This is semantically harmless but may raise generated bytes and compilation cost;
measure it explicitly and consider emitting only used bridges if the cost matters.
No estimate of tuple-allocation CPU share follows from tuple counts alone.

## Nonterminal ordinary record proposal

The type-based production rule is sound within the existing successful local
graph proof if it applies uniformly to constructors and both statement/expression
unpacking. Public outputs cannot carry newly vectorized records: the output
predicate admits only scalars or flat records of scalars. Array natives store only
U32; callbacks, foreign calls and arbitrary storage are refused by the graph.

Normalize the type before asking whether it is an existing public terminal
record. PairBox and an alias to PairBox must stay boxed. Nest and Dp are eligible
only because they have non-scalar fields and hence cannot cross the public output
boundary; their contained arrays and boxed terminal records retain identity.
Canonical Sigma remains a vector via its separate native proof. The production
rule deliberately does not copy the prototype's broader scalar-root-only PairBox
rewrite. The proposal has not yet been reviewed as executable production code.
