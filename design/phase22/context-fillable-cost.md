# Guard fillable declaration membership

Source12 is a second isolated header ablation from frozen source11. Source11's
alias guard passed checked bootstrap, maintained36 and the frozen header58; its
single TS/candidate cost preflight was healthy but does not establish a final
speed ratio. The complete contextual bundle remains unselected.

The third condition in `f_def_context_header` computes
`!f_def_fillable(old) && f_decl_taken(name, book, scope)`. Bend evaluates both
boolean operands. A fillable declaration therefore performs the membership
lookup even though the enclosing condition is already false. Put the existing
lookup behind `f_choose(Bool, !f_def_fillable(old), ..., False)`. Leave the earlier
alias checks and the later header parser in their original order. Do not change
the declaration index, lookup implementation, membership policy, or materializer.

The intended delta is one expression, no new helper, type, line, or traversal.
For valid immutable compiler books the result is unchanged. Private poisoned
books can observe less demand in the fillable branch; this is an explicit
evaluation correction, not a claim of stateful JavaScript getter equivalence.

Freeze a new source and CPU1 workflow, run genuinely checked bootstrap and the
maintained36 controls, then rerun the same frozen header58. Keep the constructor
lookup experiment separate. Any measured screen requires a coordinated exclusive
window and reports its actual sampling scope; final promotion still requires a
combined correctness gate and same-source bundle cost comparison.
