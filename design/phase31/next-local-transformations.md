# Next transformations after checked07

This is a prospective, static-only review. Keep checked07 immutable and test the
following changes separately. Neither has an established speed gain. The existing
[strict-result proof](fully-demanded-private-results.md) and
[typed layout proof](direct-private-field-reads.md) are prerequisites.

## 1. Return-position unpacking as statements

Start here: the proof and implementation boundary are smaller. In
`j_region_return`, replace only a return-position `JUnpack`'s immediately invoked
arrow with a fresh lexical block, ordered field declarations, and recursive
return emission for its arm. Expression-position unpacking keeps its current
IIFE. Preserve the proof-carried input type and exact specialized field count.
This can shorten generated code; V8 may already remove the arrow, so a neutral
speed result is plausible and should not trigger a broader rewrite.

The minimal equivalence argument is: the input is a previously demanded private
value; its own field vector is immutable; field reads have no callbacks under
the existing guard and stable-intrinsic scope; every field is captured in the
original left-to-right order before any arm operation. The new declarations have
the same lexical lifetime and shadowing as the old arrow parameters. No helper
signature, data representation, branch decision, or native operation changes.

Use a fresh block for every unpack. Either prove the existing input slot cannot
be shadowed by its new field slots, or first bind it to a fresh temporary before
introducing those slots. Preserve parallel Let RHS scope. Do **not** extend this
rewrite to the initial-zero rebinding IIFE: changing
`((p0,p1)=>body)(p1,p2)` into same-name sequential declarations can create a
temporal-dead-zone error or read the newly rebound value. Zero-field records
still execute their arm; nested unpacking must retain its own binding scope.

Fast falsification starts with generated-code shape inspection, then the existing
88-value/52-boundary structural suite. Add a compact source with repeated source
names, scalar argument prefixes, nested unpacking and parallel bindings; exercise
both initial zero and loop-to-zero entries. Retain the Array-marker mutation
witness. Run the independent fold's delayed-first-field and alias cases, followed
by the complete pair/state/native-event replay (about four seconds in this phase).
Only then freeze a small alternating comparison against07. Check generated bytes
and compiler emission cost as well as program speed; do not trade substantial
new compiler complexity for an unmeasured micro-optimization.

## 2. Fuse one native tuple producer with its private consumer

Try this separately after the statement result. The high-value candidate is the
canonical `Array.get<U32>` result consumed immediately by a known private helper
whose last ordinary parameter is completely unpacked as a canonical Sigma.
Checked07 still creates 262,401 such tuples in a complete pair. Begin with this
one producer/consumer rule, not arbitrary record flattening, multi-return ABI,
or a new ownership framework. Public helper signatures and fallback stay intact.

The additional proof obligation is **the point of the read**, not merely tuple
non-escape. Evaluate earlier call arguments, the array handle, and the index
exactly once in source order. Perform the backing-array lookup at the original
producer point, immediately preserving both the same handle identity and the
scalar read value. Then invoke the specialized private consumer with those two
values. A later write through any alias must not alter the captured scalar.
Even an unused field cannot justify dropping an effectful producer or moving
its read. The direct read must retain Array.get's checked native ownership,
index conversion, wraparound and storage behavior. Reuse the runtime read
semantics; do not silently replace them with a benchmark-specific accessor.

Require a single known consumption site and no escaping tuple identity, tuple
storage, partial application, function field or unknown consumer. Preserve all
earlier argument effects. Cases outside that proof retain ordinary tuples. A
new specialized helper needs an injective identity distinct from the original
helper and every other specialization; source names resembling generated names
must not collide. Canonical Sigma provenance, not the spelling `Tuple`, selects
this rule; shadowed native names and ordinary user constructors must refuse it.

Before a full benchmark, add alias cases where an earlier argument writes before
the read, the consumer writes before using the captured scalar, two fields carry
the same handle, and two successive gets surround a write. Include wraparound,
an unused scalar result, nested tuples, two calls to the same consumer with
different producers, and a noncanonical constructor/native refusal. The current
fold, complete-array pair oracle and hostile public entry checks remain required.
Update instrumentation prospectively: if the runtime `arrayget` call disappears,
count logical reads at the actual replacement lookup rather than reporting zero
reads or weakening the event comparison. Keep tuple-allocation counts separate
from native read/write/handle identities. A failed counterexample stops promotion.

## Admission exception for checked07

[P31-002](../../experiments/phase31/P31-002-checked-local-regions.md) originally
required no material scalar/runtime regressions, and
[final integration](final-integration.md) rejects material disjoint slowdowns
pending investigation. The measured +4.01% zero-work cost (about 0.182 microseconds
per call) and +5.04% complete generic-row cost (about 21.15 microseconds) must stay
recorded as regressions. The large measured gains—29.09× on the full pair and
17.67× on the independent fold—do not turn those observations into passes.

My recommendation is a **documented, bounded admission exception**, conditional
on the frozen [registration diagnostic](generic-registration-diagnostic.md)
meeting its stated causal criteria and the remaining release gates succeeding.
Its unused-registration perturbation can explain generic-call overhead; it does
not by itself establish the cause of the separate zero-work cost or a safe fix.
Keep that distinction in the report, including any unexplained residual.

Before promotion, append the explicit exception and its rationale to P31-002
and the final-integration decision: identify exact artifact and receipts, retain
the original failed no-regression result, describe the two affected workloads
and absolute costs, and label the outcome "admitted with measured regressions".
This exception applies only to these measured costs in this candidate; it is not
a relaxed threshold for future changes. Do not redefine the original criterion
after seeing results or average the slowdowns into an overall speed score.
Registration overhead becomes a separate bounded optimization question, while
statement lowering and tuple fusion retain their own prospective gates.
