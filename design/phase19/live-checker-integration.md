# Live checker integration gates

The Phase19 isolated checker now checks and produces each live instance in the
ordinary checker. Before considering installation, compare source04/build03
(`a15d150a`) with the installed prefix-corrected release (`66d6ce45`). The parser
prototype is excluded. This plan is prospective for the cost comparison and
promotion; the broad frontend run was launched before writing this addendum.

The central simplification removes the second recursive specialization visitor.
The source book remains authoritative for lookup and substitution; the checked
book is output. This closes the two saved instance chronology differences and
passes the six let-close observations. Source04 has 15,880 physical lines versus
16,355 installed: 475 fewer lines, 56 fewer law declarations, but two more
definitions and one more type. This is a removal of a semantic traversal, not a
claim that every complexity measure falls.

The new checked output is published in completion order, placing nested instances
before their callers. This is an intentional raw-book order change; repeated
checking/specialization and emitted behavior must be tested. Prefix checking
currently replays source events because the existing cache does not contain the
instance memo and checked output. This preserves one semantic authority but can
cost time. The host cache format and public result shapes remain unchanged.

assembled compiler source for every variant, and the complete exact host-file
review. Baseline is prefix-build-01; candidate is instance-build-03. Both must use
the same pinned Base, runtime, profile and host membership/bytes.

Run TS/B/C/C/B/TS serially in fresh CPU0 processes with the existing4MiB stack and
4GiB heap. First obtain all owners' confirmation that compiler, probe and archive
jobs are closed; hold new launches through matrix completion. Keep separately
validated Bend Base caches, TypeScript's Base checking, and unflushed OS caches
explicit. Process wall includes startup/hash/output handling; request timing
includes lazy API loading. Record every sample and peak RSS. Require actual
type acceptance and the expected unsafe-definition trust refusal/sets for all
rows. No emission or generated-program speed is measured here.

A process regression above5% triggers investigation before promotion. A smaller
delta is only a screen; do not call noise a speed gain. Compare the TS ratio in
this same window, never multiply earlier phase percentages. If correctness or
cost fails, retain the candidate, actual failure and installed usable release;
isolate the cause in a fresh source/build before repeating relevant gates.
