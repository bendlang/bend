# Phase19 event and public-result boundary

Prospective addendum to [live checking](live-instance-checking.md) and its
[interfaces](instance-interfaces.md), frozen before root-owned compiler edits.
The root owns diagnostic/produce, check/prefix and driver/api in the isolated
instance-source-01 project. No installed source or host ABI changes here.

`dg_check_world(book) -> DChecking` is the sole source-event runner. It builds
one declaration index and one empty event index from the original source maximum,
uses `kw_seed`, and threads the actual returned world through every successful
event. It has no open-law or program TODO completion policy. On the final event
for a name, it publishes original source d and completed checked output. Generic,
ADT, foreign and absent bodies keep original output d; ordinary bodies use ct.
Instances are published by the kernel and never become source events.

`dg_checking_result` projects the actual KChecking for specialize_book. A failed
check retains its failed semantic book and deepest structured trace owner. The
source-event boundary qualifies its error once. It derives the diagnostic from
the original unqualified payload and locates spans only at the public adapter.
Successful check_book diagnostic calls still return the original input book and
apply the historical open-law completion policy. Program checking returns the
output assembler's completed book, then checks original-source TODO count.

The existing validated-prefix payload holds source only, without live-instance
memo or checked output. The first correct prototype therefore replays all events,
even for an exact supplied prefix; it does not pretend to restore missing state.
The host cache format remains unchanged. This may cost time; a controlled final
comparison must quantify it before promotion. No guess that Base has no templates.

The still-public exact_prefix guard has two independent syntax-identity omissions:
compact literal payload and lambda quantity presence. Add literal kind/number/text
comparison and lambda presence equality. Compact literal and expanded constructor
syntax remain distinct. Preserve historical omission of source spans; source
identity remains the host's provenance obligation. Controls include changed
numeric and text literals, implicit versus explicit lambda quantities, equal
values, old explicit KTerm lambdas and compact versus expanded spelling.

First gates are saved22 chronological comparisons and memo8. Old public18's
invalid-instance check_book-success assertion is an intended semantic change;
shape/projection/immutable demand controls remain applicable. Whole-result
comparisons must separate that semantic change from accidental output differences.
Focused prefix, failed-world, law-fill, generic, foreign and emitted-output tests
precede full conformance and timing. No timing or conformance gain is claimed by
this plan.
