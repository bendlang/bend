# Compact-query clean screen

The two prototype correctness arms pass all30 complete observation/output
comparisons. The prefix prototype is not a winner: its full-state equality
still visits about362,000 objects on the small body edit. Its combined process
also retains substantial memory. Keep that evidence; test emitter-local query
reuse independently in fresh processes before extending checkpoint reuse.

Freeze four serial worker processes in order baseline, compact, compact,
baseline. Each loads the same actual checked07 driver/API/runtime/Base/cache,
executes small positive, original Mandelbrot and original edit distance once as
warmup, then the same three requests once as screen samples. No old prefix
state or hash counters are loaded. Candidate query caches live only during one
emission export. All cache/trie work remains inside the normal request. Existing
API loading occurs before these warmed requests; this screen therefore cannot
replace Phase31's fresh normal-request metric. Report the first triad separately.

Each request's full observation/dependency list and output hash must equal its
previous unmodified07 correctness oracle. Pre/post all inputs and Base cache
hashes are checked. Bind exact worker, plan, API derivative appendix and Node
binary. CPU2,4MiB stack,2GiB V8 heap; outer120seconds, child60seconds. Launch only
after root grants an exclusive window. Preserve every process outcome. No
median over survivors and no comparisons to earlier instrumented runs.

Two timed samples per role/case are an inexpensive screen, not a promotion
measurement. Advance only if request medians improve at least3% on both larger
programs and ranges are disjoint on one, with no greater5% small-program
regression. Otherwise reject or call it inconclusive before additional work.
Memory and source/representation complexity remain separate admission axes.
