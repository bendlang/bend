## Ordered investigation

1. Verify the installed release. Sample its actual immutable checking workload
   without changing production. Preserve the raw10ms CPU profile, exact inputs
   and lexical-owner summary. Sampling identifies a target; it is not a speed
   measurement and does not attribute GC/dispatch to inferred callers.
2. Reread the pinned TypeScript checker and compiler alongside Bend implementations.
   Compare algorithms, representation, traversals, branch lowering and knowledge
   available at each call. Separate new evidence from earlier rejected generic
   walkers, semantic-value replacements and low-gain ordinary uncurrying.
3. Run three independent bounded investigations: repeated pattern reconstruction
   and emitted-code size; checker/normalization work; generated branch/call work.
   Each records a falsifiable plan before probes, starts with small scaling and
   semantic counterexamples, then builds an isolated checked candidate only if
   justified. Root can add another named hypothesis when refreshed evidence
   exposes a distinct opportunity. Preserve all failed and superseded attempts.
4. Review invariants independently and integrate survivors sequentially. Global
   changes need global invariants and applicable caller/ABI/ownership/error-order
   controls. Do not edit the pinned upstream or silently remove a validation pass.
   Preserve baseline observations unless an explicitly demonstrated semantic fix
   justifies a changed result. Keep safe fallbacks for valid unsupported shapes.
5. Build a final checked candidate, run focused and relevant actual JS/native
   execution gates, and compare the complete frontend vector against Phase10 and
   the same-pin retained TypeScript reference. New representation changes require
   literal/binder/alias/erasure/readback and demand-order witnesses as applicable.
6. Freeze source and pause intentional competing jobs for serial fresh-process
   TS/baseline/candidate/candidate/baseline/TS checking. Measure deep patterns
   separately if affected. Publish all rows, memory, input identities and scopes.
7. Install a justified candidate, verify ordinary/relocated CLI behavior, update
   documentation and report, preserve recoverable experiment evidence, commit and
   push. Rejected ideas are reported without promotion. No fresh self-hosted fixed
   point, Lean proof or GPU validation follows from a checked B1 release.

## Measurement and integration policy

Use Node24.18.0,4MiB stack,4GiB heap for comparable workers; preserve the nested
bootstrap's actual resource policy rather than assuming flags propagate. Use
unchanged Base/runtime unless a hypothesis explicitly changes and validates one.
Each Bend variant uses its own validated Base cache; TypeScript checks Base. OS
cache is not flushed. Separate request time, process time, generated-program
execution, checked developer-loop latency and peak RSS. Two samples are descriptive,
not a confidence interval. Micro/operation speedups are not whole-compiler gains.

CPU0 belongs to root profiling/final measurements; independent tiny screens use
CPU1/2/3. All intentional compiler/archive jobs pause for final controlled timing.
Use the approximately26-second checked/focused loop for normal iterations.
Root owns integration, release and serial comparisons. Keep source/API/runtime/
Base/host/harness hashes, original failures and exact histories. Unrelated dirty
Phase6 files and historical immutable attempts stay unchanged.
