1. Verify the installed release and preserve unrelated dirty Phase6 identities.
   Profile the actual final Phase11 checking workload on CPU0 using the unchanged
   diagnostic runner. Keep full raw10ms samples, exact inputs and lexical-owner
   summary; runtime/GC remain separately attributed. No candidate code before its
   prospective hypothesis record. Other investigators begin with static reading.
2. Compare the current Bend code, generated checked image and pinned TypeScript.
   Rank delayed normalizer fallback, residual branch/call lowering, and remaining
   rediscovered structure or literal expansion using fresh evidence. Each owner
   gets a roughly20-minute initial screen, reports after a decisive result, and
   must justify expanding scope. Previously rejected unconditional checked-output,
   generic binder and semantic-value designs do not become new proposals by name.
3. Count avoidable operations on small valid source families. Challenge demand,
   error order, bindings, substitution, constructor identity, quantities, imports
   and foreign boundaries. A generated-image experiment must explicitly separate
   the checked parent, derivative and emitted user code. Any new transform version
   must retain exact historical v1/v2/v3/v4 replay and reject unknown shapes.
4. Build promising source candidates through the maintained checked B1 workflow
   in isolated project copies. Preserve every failed attempt, compiler artifact,
   consumed tool and boundary control. No live production edits by investigators.
   Microtimings are a screen; only a controlled combined comparison earns a
   whole-workflow speed claim. All process launch errors/signals invalidate timing
   even when an exit status is zero and a worker result happens to exist.
5. Independently review survivors, then integrate sequentially. Run the21 focused
   controls and relevant component/actual JS/native gates. Compare a fresh complete
   candidate frontend vector with Phase11 and retained unchanged-pin TypeScript;
   preserve exact differences rather than changing fixture oracles to hide them.
   Compact-literal changes require all representation consumers and runtime
   boundaries to be validated; defer them if a small experiment cannot establish
   a safe profitable boundary.
6. Freeze the final candidate and pause all intentional compiler/archive jobs.
   Run serial fresh-process TS/baseline/candidate/candidate/baseline/TS checking on
   the identical final source. Use a separate ABBA Nat300 JS/native comparison
   when affected; preserve generated bytes, correctness and actual execution
   separately from emission timing. Two samples are descriptive, not confidence
   intervals. Negative or marginal gains can cause a candidate to be dropped.
7. Install only a justified candidate; verify ordinary and relocated use, update
   the README-linked compiler documentation and the canonical report, preserve
   recoverable evidence, commit and push. A well-supported deferred result is
   preferable to installing complexity without benefit. Full checked B1→H→H,
   kernel proofs and GPU execution remain separate future gates.
