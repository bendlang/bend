# Prospective record-loop boundary amendment

Frozen after independent static review of prototype-record-loop-01 and before
new controls/derivation. The initial result's immutable recursive G scope remains.
The reviewer identifies an additional raw-callback limitation: an object in the
predecessor slot is coerced by the original recursive prefix, then the private
loop coerces it again because the projected next descriptor was discarded.

Retain a differential witness against01. Derive02 with a primitive BigInt
predecessor required for private transfer. All other values return the original
already computed bounce, so no argument or projection is repeated. Rerun full
oracles and ordered controls, including the new witness. Archive consumed tools.

A separate subsequent guarded variant may capture each recursive G target before
next arguments, inspect original descriptor data properties without invoking
accessors, and fall back using that already captured target if identity or
internals changed. The guard belongs before next argument expressions because
the original recursive prefix is forced before the cell. Mid-cell mutations
become visible at the following recursive prefix; the current callback retains
the previously selected body. This is a proposed experiment, not permission to
assume immutable globals in production. It requires independent controls for
replacement, in-place code/arity/env/bound changes and lookup-side effects before
timing, and may erase the measured mechanism advantage.
