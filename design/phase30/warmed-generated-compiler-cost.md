# A small warmed H versus genuine checked-parent request

Prospective bounded follow-up to the successful16 B1→H acquisition. Compare H
with the genuine checked bootstrap parent from the same final16 assembled source,
not with a fabricated H development manifest. The genuine parent is TypeScript-
produced JavaScript for this same Bend compiler; it is not the upstream compiler
implemented in TypeScript. Keep the selected equality API
used for the B1→H acquisition separately identified. This answers the cost of one
small ordinary checked-library request through the real host adapter; it does not
measure a fixed point, large selfcompile, whole compiler suite or steady state.

Use the exact already-validated positive Nat/U32 fixture from self-emission16,
unchanged Base/runtime, Node24.18.0 and frozen typed driver/positional ABI adapter.
The shared runtime is the runtime supplied to emitted output; the two compiler
APIs' embedded runtime/representation and real adapter costs belong to the
compared implementations. Both sides emit the same independently retained
JavaScript bytes and run to8.
First acquire a separate preparation gate for each actual API hash: import and
validate ABI, genuinely prepare or validate its Base cache, emit the fixture and
execute it. The checked parent's cache must not be relabelled from the selected
B1 API; H's cache must retain its actual-H hash. Bind successful preparation
receipts and unchanged cache bytes before the timing plan can be used.

The exclusive CPU0 measurement has three alternating fresh-process trials per
side: parent/H, H/parent, parent/H. Each child has a90-second process deadline,
4MiB V8 stack and8GiB heap allowance on both sides. Import, ABI validation and
Base-cache preparation/validation occur before all request timers. Keep one
loaded API in each process, execute exactly one untimed warm library request,
then two timed `D.inspect(source,{mode:'library',api})` calls. Normal source
discovery, checking, emission, cache reading/validation and H's real ABI
conversion remain inside those request timers. Disable trace output on both
sides. Output hashing, file persistence and verification happen after each
request timer; every warm and measured output must match the independent hash.

Report all warm/timed request values, each trial's two-call mean, the median/min/
max of three trial means, second-versus-first change within each trial, and the
same-window H/parent ratio. One warm request is deliberately a fixed small
protocol, not a claim of convergence. Large within-trial change or overlapping
ranges must remain visible. Do not multiply this ratio by earlier compiler or
program timings. Process wall time, preparation and RSS remain separate.

Preparation may overlap correctness acquisition onCPU2 after a root grant.
Measurement requires its own clean grant after every other acquisition closes;
it must not overlap the original-program/compiler matrix. The existing library
cost runner requires development manifests and remains unchanged: this new small
runner binds the actual checked-parent artifact and generated-H receipt directly.
No compiler/runtime source edit, H installation, H→H emission or new cache policy
is part of the experiment.
